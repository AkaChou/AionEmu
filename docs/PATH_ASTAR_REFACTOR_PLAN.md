# A* PATH 寻路重构方案

> 状态：P0/P1 已实施；P2-A 已加入参考 HPA* 的长距离 block/portal 分层寻路，并保留完整低层 A* 回退；等待真实副本压测
>
> 范围：地面 NPC 为主，继续使用当前 `PathData` A* 与真端 PATH 数据；飞行/游泳沿用现有空间寻路，后续按相同恢复框架接入。
>
> 核心目标：怪物遇到坡地、障碍物、拥挤和移动目标时能够持续前进、自动恢复，并且在怪物数量增加时不造成 A*、GEO、移动线程或网络广播失控。

## 1. 结论

不重写 A*，也不新建第二套导航系统。重构重点放在 A* 的上层使用方式：

1. 用低成本进度监测可靠识别 Stuck，而不是只等某次 `canMoveStraight` 返回失败。
2. 确认 Stuck 后先做廉价恢复，再异步重新执行 A*。
3. 重新执行 A* 时必须临时排除刚刚失败的路段；直接用相同起终点重算只会再次得到同一路径。
4. 正常 A* 仍只使用 PATH 拓扑，不在每个扩展边上执行 GEO 射线检测。
5. 路径生成后做 PATH Line of Sight 平滑，只对最终保留的少量长线段做 GEO 校验。
6. 移动阶段使用有限前视 Waypoint Skip，不在每个 100ms tick 扫描整条路径。
7. 局部避障复用 `NpcCrowdManager`，候选顺序改为左右 `15°/30°/45°`，候选 Z 投影回同一 PATH 层。
8. 多只怪追同一玩家时分配稳定的目标环形位置，不让所有 A* 都瞄准玩家中心。
9. 连续失败时先寻找同层最近 PATH 节点，再执行现有 `pull_target`、`abandon_target` 或 `return_to_sp` 策略；回家仍失败才允许超时传送。
10. 跨至少 8 个官方 PATH block 的长距离地面路径先执行 block 抽象 A*，再按 portal 逐 block 细化；任一细化段失败都回退普通低层 A*。

推荐实施顺序是：

```text
可观测性与 Stuck 检测
    → Stuck 后带失败路段排除的 A*
    → 有界 Waypoint Skip
    → 15°/30°/45° 局部避障
    → 稳定目标点偏移
    → 最近 PATH 节点与最终回家兜底
    → 长距离 block/portal 分层寻路
    → 根据实测数据再做请求合并和自适应限流
```

## 2. 当前事实与约束

### 2.1 现场 Z 轴验证

2026-07-17 对地图 `210010000` 的两个坡地位置进行了运行时采样：

| 位置 | 角色 Z | GEO Z | PATH Z | GEO/PATH 差值 | PATH 状态 |
|---|---:|---:|---:|---:|---|
| `650.514893, 1048.812988` | `101.065720` | `101.066719` | `100.984375` | `0.082344m` | `FOUND` |
| `648.836792, 1035.241089` | `100.055405` | `100.056404` | `100.062500` | `0.006096m` | `FOUND` |

两个位置都只有一个附近 PATH 层，差值远小于 PATH 当前 `< 0.7m` 的选层容差。当前证据不支持“坡地卡住主要由 GEO/PATH 静态 Z 层错位导致”。优先级应放在运行时进度检测、拥挤、局部步进、路径失效和恢复，而不是再次用 GEO 覆盖 PATH Z。

### 2.2 当前运行链

```text
AttackManager / AI
        │
        ▼
NpcMoveController
  - 每 100ms 由 MoveTaskManager 推进
  - 保存缓存路径和在途请求
  - 跟踪移动目标并决定是否重寻
        │
        ▼
PathService
  - 异步优先级队列
  - A* 请求超时、队列容量、结果缓存
  - 地面 PATH / GEO 回退 / 空间寻路
        │
        ▼
PathData.MapData.searchAStar
  - 0.5m PATH 网格
  - 8 方向 A*
  - 真实 PATH Z
  - SearchStatus 与 processedNodes
```

### 2.3 当前已有能力

必须保留并复用以下实现：

- `MoveTaskManager.UPDATE_PERIOD = 100ms`，移动帧已并行执行。
- 追击目标漂移阈值 `CHASE_REPATH_DISTANCE = 2m`。
- 有中间路点时不会因目标轻微移动立即丢弃路径。
- 同一可达性检测有 `100ms` 短缓存。
- A* 使用独立 worker，当前自动 worker 数为 `CPU / 2`、最多 `8`；10 核机器会使用 `5` 个。
- 异步队列容量 `256`，追击请求超时默认 `250ms`，位置/回家请求至少 `1000ms`。
- A* 最大展开节点数 `50000`。
- 结果缓存按约 `2m` 起终点格量化，TTL `500ms`，最大 `1024` 项，并包含实例动态障碍版本。
- `PathService.simplifyPath` 已进行 PATH 拓扑 Line of Sight 压缩。
- 跨至少 8 个 block 的长路径可先走 block 抽象 A*，按真实跨块 portal 逐段细化；失败自动回退普通 A*。
- `NpcCrowdManager` 已有 4m 空间桶、邻居速度预测、候选早停和 GEO 检测锁外执行。
- 当前失败后每秒尝试一次局部恢复，最多 4 次，5 秒后进入 AI 的失败策略。
- 当前失败策略支持 `pull_target`、`abandon_target`、`return_to_sp`。
- 当前回家支持巡逻点或出生点、30/60 秒超时以及最终位置恢复。
- PATH 路点的 Z 已被完整保留，不再逐点重新投影为 GEO Z。

### 2.4 重构前主要缺口

1. **没有真正的移动进度 Stuck 检测。** 目前主要依赖下一路点可达性、局部候选是否存在或已明确的寻路失败；怪物可能一直持有“理论可达”的路径，但实际位置长期没有有效前进。
2. **直接重跑 A* 可能重复原路线。** PATH 图和起终点不变时，确定性 A* 会再次选择相同的第一路段。
3. **正常路线与恢复路线缺少失败路段上下文。** 当前 A* 不知道 NPC 刚在哪一段实际走不动。
4. **局部避障角度和 Z 处理不适合坡地。** 当前候选以 30° 环绕；斜向候选的垂直分量不应随二维旋转角度缩放或翻转，候选 Z 应来自同一 PATH 层。
5. **所有怪物仍以目标中心为寻路终点。** 虽然移动会按攻击距离停止，但大量 NPC 的路径终点和末段方向仍高度重合。
6. **运行时 Waypoint Skip 不完整。** 生成路径时已有平滑，但目标移动、局部避障或动态障碍变化后，控制器不能低成本地跳过已经多余的近路点。
7. **异步请求读取可变对象。** 缓存键在提交时取坐标，worker 执行时仍可能读取 NPC 的新坐标；队列延迟下，缓存键、实际搜索起点和结果应用时刻可能不完全一致。
8. **结果语义分散。** `null`、空数组、异常分别表示无路、瞬时失败或未完成，恢复策略和指标容易混淆。

## 3. 按效果与成本排序

评分：效果与成本均为 1～5；运行成本表示功能启用后的持续 CPU/GEO/A* 压力。

运行成本中的负数表示该项预期减少总体压力，但仍需先用基线指标证明收益。

| 排名 | 能力 | 预期效果 | 实现成本 | 运行成本 | 当前基础 | 推荐阶段 |
|---:|---|---:|---:|---:|---|---|
| 1 | Stuck 进度检测 | 5 | 2 | 1 | 缺失 | P0 |
| 2 | Stuck 后带失败路段排除的 A* | 5 | 3 | 3 | 只有普通重寻 | P0 |
| 3 | 有界 Waypoint Skip | 4 | 2 | 2 | 只有生成期平滑 | P0/P1 |
| 4 | `±15°/±30°/±45°` 局部避障 | 4 | 2 | 2 | 已有 30° 候选与拥挤预测 | P1 |
| 5 | 稳定目标点动态偏移 | 4 | 3 | 1 | 仍瞄准中心 | P1 |
| 6 | 最近同层 PATH 节点恢复 | 3 | 3 | 1 | 缺失 | P1 |
| 7 | 路径平滑与最终线段 GEO 校验 | 3 | 2 | 1～2 | 已有 PATH LoS 平滑 | P1 |
| 8 | 请求快照、结果代际和明确状态 | 4 | 3 | 1 | 部分具备 | P0 基础项 |
| 9 | 同键在途请求合并 | 3～5 | 3 | -2 | 只有完成结果缓存 | P2，按指标决定 |
| 10 | 自适应限流与分级 A* 预算 | 3 | 4 | -3 | 有固定队列/超时 | P2，按指标决定 |

说明：

- “路径平滑”排名较低不是因为不重要，而是当前已经存在贪心 PATH LoS 压缩；本次只需补最终线段校验和运行时跳点。
- “最近 PATH 节点/回出生点”是终局兜底，能减少永久卡死，但不能替代前面的恢复步骤，否则怪物会频繁消失、瞬移或脱战。
- “请求合并”和“自适应预算”不应先做。先取得真实队列等待、A* 节点数和 Stuck 恢复数据，再决定是否值得增加复杂度。

## 4. 设计原则

### 4.1 保持职责边界

| 组件 | 保留职责 | 新增职责 | 不应承担 |
|---|---|---|---|
| `PathData` | PATH 数据、选层、节点、A*、PATH 直线可达 | 最近同层节点查询、恢复期廉价边过滤 | AI 策略、时间重试、回家 |
| `PathService` | 异步调度、缓存、地面/空间路径、压缩 | 请求快照、恢复上下文、最终段校验、指标 | 每只 NPC 的 Stuck 状态机 |
| `NpcMoveController` | 路点消费、追击、移动帧、回家 | 进度检测、恢复阶段、Waypoint Skip、目标槽位 | 扩展 A* 节点、全局队列管理 |
| `NpcCrowdManager` | 邻居预测、候选选择 | 有序角度、同层候选投影、稳定左右偏好 | 全局 A*、回出生点策略 |
| `TargetEventHandler` | 真端失败反应 | 只接收“恢复已耗尽”事件 | 每次暂时不动就立即回家 |

不新增独立导航线程、不新增第二份地图数据、不引入 ORCA/RVO 库，也不把恢复逻辑塞入 AI Pattern。

### 4.2 PATH Z 是移动高度权威

- 地面 PATH 路线一旦选层，所有路点、平滑点、跳点和局部候选都必须保持该 PATH 层 Z。
- GEO 用于碰撞、视线和最终线段通行校验，不用于覆盖已有 PATH 路点 Z。
- 局部候选必须先投影到与当前路点相同的 PATH 层；找不到同层节点就拒绝候选。
- 只有没有 PATH 数据或 PATH 位置无效时，才允许走当前 GEO fallback。

### 4.3 正常路径廉价，恢复路径按需变重

正常情况下：

```text
PATH A* → PATH LoS 平滑 → 少量最终线段 GEO 校验 → 移动
```

确认 Stuck 后：

```text
Waypoint Skip → 局部角度候选 → 排除失败路段的 A* → 最近同层节点 → AI 失败策略
```

禁止在正常 A* 的每一条候选边上调用 `GeoService.canPassWalker`。一次 50000 节点搜索可能扩展大量边，怪多时会把普通 A* 放大成 GEO 射线风暴。恢复期应先使用一两个廉价的“失败 PATH 格/边”过滤条件，得到路线后再校验最终少量线段。

### 4.4 HPA* 参考与当前适配

参考实现：[hugoscurti/hierarchical-pathfinding](https://github.com/hugoscurti/hierarchical-pathfinding)。该项目把静态二维网格划分为多级 Cluster，预计算 Cluster 边界入口间的 Intra 路径；查询时临时把起终点接入边界节点，在最高抽象层执行 A*，再通过 `UnderlyingPath` 逐层细化。

参考项目的核心不是简单缩小搜索矩形，而是：

- `INTER` 边表示跨 Cluster 入口。
- `INTRA` 边表示 Cluster 内入口之间的低层路径。
- 高层 A* 得到入口链后，通过 `UnderlyingPath` 逐层还原低层路径。
- 起点和终点是查询时临时接入抽象图的节点，查询结束后移除。

当前 Aion 适配采用同样的职责分离，但不复制 Unity/C# 对象模型：

- 不重新按任意尺寸切网格。官方 PATH 已有 `32×32` 半米格 block、sector 和 portal table，应直接把 block/portal 作为天然 Cluster/入口。
- 跨至少 8 个 block 时，先在官方跨块连接上执行 block 级 A*，最多展开 2048 个抽象 block。
- 抽象结果不直接作为移动路径；每个 block 内仍使用现有 PATH 节点与 Z，搜索可达的下一跨块 portal，再沿真实 portal 边进入下一 block。
- 所有 block 内 `INTRA` 细化共享 8192 个低层节点预算，避免抽象失败时先消耗完整 50000 节点。
- `BlockedSegment`、动态门和实例障碍仍在每个低层 `INTRA/INTER` 段重新验证；抽象层不覆盖运行时碰撞语义。
- 任一 portal 不可达、层不一致、细化超预算或抽象 block 连通性过粗时，立即用原起终点执行普通低层 A*。
- block 邻接只按需缓存，不预计算所有入口对之间的路径，避免 185 张地图启动时产生大规模 CPU 和内存开销。
- 短路径、Waypoint 检查、飞行和游泳不进入分层逻辑。
- 参考项目是静态二维单层图，不处理 Aion 的多层 Z、飞行、游泳、GEO 碰撞和怪群局部避障，因此不直接移植其 Unity/C# 对象模型或代码。

这属于 HPA* 思路的一层、惰性版本：保留 `Cluster → Portal → Intra refinement`，但不建立第二份全量节点图，也不预计算 all-pairs `UnderlyingPath`。

## 5. 请求与结果模型

### 5.1 不可变请求快照

异步 worker 不应重新读取会变化的 NPC 起点。提交时创建最小请求快照：

```java
record PathRequest(
    long requestId,
    int ownerId,
    int worldId,
    int instanceId,
    float startX,
    float startY,
    float startZ,
    float targetX,
    float targetY,
    float targetZ,
    MovementMode mode,
    float clearance,
    long obstacleVersion,
    BlockedSegment blockedSegment
) {}
```

约束：

- `start*`、`target*`、`obstacleVersion` 与结果缓存键必须来自同一快照。
- `ownerId` 只用于日志和结果归属，不在 worker 中重新获取实时坐标。
- `MovementMode` 最少区分 `GROUND`、`FLYING`、`SWIMMING`。
- `clearance` 只需按碰撞体半径分桶，不需要保存完整 NPC 对象。
- 普通请求的 `blockedSegment` 为空；只有恢复请求携带一个短期失败路段。
- 第一阶段如果不想一次改完接口，至少要先快照起终点，并确保缓存键和 A* 使用同一组数值。

### 5.2 明确结果状态

当前 `float[][] / null / empty / exception` 语义应收敛为一个小结果类型：

```java
record PathPlan(
    Status status,
    float[][] waypoints,
    int processedNodes,
    long queueMicros,
    long searchMicros,
    long requestId,
    long obstacleVersion
) {}
```

建议状态：

| 状态 | 含义 | 控制器行为 |
|---|---|---|
| `FOUND` | 找到有效路线 | 安装路径并清理失败上下文 |
| `NO_PATH` | 图上确认无路 | 进入恢复阶梯，不做高频重试 |
| `INVALID_POSITION` | 起点或目标不在有效 PATH 层 | 尝试最近同层节点或 GEO fallback |
| `NODE_LIMIT` | 达到节点预算 | 瞬时失败；冷却后有限重试 |
| `TIMEOUT` | worker 执行超时 | 瞬时失败；保留旧路径 |
| `QUEUE_EXPIRED` | 排队过久 | 瞬时失败；禁止立即回家 |
| `REJECTED` | 队列满 | 瞬时失败；退避并保留旧路径 |
| `CANCELLED` | 被新目标/新代际取消 | 静默丢弃 |

若第一阶段不引入 `PathPlan`，也必须在控制器内部保持同样的分类，不能把队列满、搜索无路和位置无效都当成一种失败。

### 5.3 结果代际

- 每次新目标、目标切换、障碍版本变化或恢复重算时递增 `requestId`。
- 结果完成时只有 `requestId` 仍等于控制器当前代际才允许安装。
- 起点已经移动超过建议 `1.5m` 时，不直接安装旧路径；可以尝试从当前坐标跳入路径中可直达的最远前置路点，否则丢弃并重寻。
- 目标相对请求终点漂移不超过现有 `2m` 时保留中间路径；超过才使其失效。

## 6. Stuck 检测

### 6.1 检测目标

Stuck 表示：NPC 当前应该移动、确实有目标或路点、没有被合法控制，但在一段时间内没有取得足够的“沿路线有效进度”。

不能只用三维位移判断：

- 下坡时 Z 变化和网络插值会放大视觉抖动。
- 拥挤时 NPC 可能横向避让，实际位移不小但没有接近路点。
- 玩家移动时目标距离可能保持不变，但 NPC 仍在沿路线前进。
- Root、Stun、施法、攻击停距、等待异步路径都不是 Stuck。

### 6.2 O(1) 进度状态

在 `NpcMoveController` 内增加少量原始字段，不创建每 tick 对象：

```text
progressSampleAt
progressX / progressY / progressZ
progressWaypointX / Y / Z
progressRemainingDistance
lastMeaningfulProgressAt
noProgressWindows
recoveryStage
recoveryStartedAt
replanAttempts
lastRecoveryActionAt
```

采样频率建议 `500ms`，而不是每个 `100ms` tick 都判定。tick 内只使用已有坐标做一次时间比较。

### 6.3 有效进度计算

设：

- `P0` 为上次采样位置。
- `P1` 为当前位置。
- `W` 为当前路点。
- `D = normalize2D(W - P0)` 为预期水平移动方向。
- `M = P1 - P0`。
- `projected = dot2D(M, D)` 为沿路线方向的有效进度。
- `remainingDrop = distance3D(P0, W) - distance3D(P1, W)`。
- `expected = speed * sampleMillis / 1000`。

满足任一条件即可视为有效进度：

```text
projected >= max(0.10m, expected * 0.15)
remainingDrop >= max(0.10m, expected * 0.15)
当前路点已被消费
路径代际发生变化且新路径已安装
```

推荐默认值：

| 参数 | 默认值 | 目的 |
|---|---:|---|
| 采样周期 | `500ms` | 降低计算量并过滤单 tick 抖动 |
| 最小有效进度 | `0.10m` | 高于浮点和小幅位置噪声 |
| 期望进度比例 | `15%` | 允许拥挤、转弯和慢启动 |
| 疑似 Stuck | 连续 `2` 个失败窗口 | 约 1 秒 |
| 确认 Stuck | 连续 `3` 个失败窗口 | 约 1.5 秒 |

这些值是起始值，最终应根据指标调整。低速巡逻 NPC 可把确认窗口延长到 `2～2.5秒`，战斗追击保持约 `1.5秒`。

### 6.4 必须暂停或重置检测的情况

以下情况不累计 Stuck：

- `owner.canPerformMove()` 为 false。
- AI 正在施法或处于临时控制效果。
- 已进入攻击距离，控制器本来就应该停下。
- 没有缓存路径且正在等待尚未超时的异步请求。
- 当前目的地已到达。
- NPC 正在被强制移动、击退、拉取或传送。
- 路点刚切换、目标对象刚切换、路径代际刚更新。
- 服务器本 tick 延迟异常；采样间隔超过正常值太多时重置基线，不把服务器卡顿算成 NPC Stuck。

### 6.5 Shadow 模式

第一阶段先只检测、不改变移动行为：

- 记录 `stuckSuspected`、`stuckConfirmed`。
- AI 调试开启时记录 NPC、地图、实例、坐标、路点、速度、有效进度和路径代际。
- 聚合统计误报：检测后下一个采样窗口是否自行恢复。
- Shadow 模式运行一轮副本和怪群压力测试后再启用恢复动作。

## 7. 恢复状态机

### 7.1 状态

只增加一个小枚举，不再叠加更多互相依赖的布尔变量：

```text
NORMAL
SUSPECTED
LOCAL_ESCAPE
REPLAN_PENDING
REJOINING
EXHAUSTED
```

`Destination.HOME` 仍表示业务目的地，`RecoveryStage` 只表示当前移动恢复阶段，二者不要合并。

### 7.2 恢复顺序

```text
确认 Stuck
  │
  ├─ 1. 当前路径能否跳到更远路点？ ──成功──> REJOINING
  │
  ├─ 2. 尝试 ±15° / ±30° / ±45° ──成功──> REJOINING
  │
  ├─ 3. 记录失败路段并重新 A* ──成功──> REJOINING
  │
  ├─ 4. 查找最近同层 PATH 节点并重算 ──成功──> REJOINING
  │
  └─ 5. 恢复耗尽
          ├─ 战斗：按 npc-ai 的 pathfind fail reaction
          └─ 回家：继续回家超时策略，最终位置恢复
```

任何阶段只要在一个 `500ms` 采样窗口取得有效进度，就回到 `NORMAL`，清理临时失败路段和尝试次数。

### 7.3 时间线建议

从“确认 Stuck”开始计时：

| 时间 | 动作 |
|---:|---|
| `0ms` | 尝试有界 Waypoint Skip |
| `0～800ms` | 最多 2 次局部角度恢复，间隔至少 `300～400ms` |
| `800ms` 后 | 提交第一次带失败路段的 A* |
| `1600ms` 后仍失败 | 允许第二次 A*，扩大失败路段一格或更换目标偏移槽 |
| `2500～3500ms` | 查找最近同层 PATH 节点并重算一次 |
| `5000ms` | 沿用当前 AI pathfind fail reaction |

限制：

- 每只 NPC 同时最多一个 A* 请求。
- 普通重寻与恢复重寻共享冷却，建议最短 `500～750ms`。
- 同一次 Stuck 事件最多 2 次普通恢复 A* 加 1 次最近节点 A*。
- 目标明显移动、动态障碍版本变化或 NPC 已取得有效进度时，清零本次恢复计数。

## 8. Stuck 后重新执行 A*

### 8.1 为什么不能原样重算

当前 PATH 图、起点、目标和启发函数不变时，A* 是确定性的。若 NPC 因 PATH 数据未表达的小障碍、坡地局部碰撞或运行时拥挤卡住，原样重算大概率返回相同的第一路点和相同路线。

因此恢复请求至少要带一个只属于该 NPC、短 TTL 的失败路段：

```text
lastProgressPosition → currentWaypoint
```

### 8.2 失败路段表示

推荐最小表示：

```java
record BlockedSegment(
    float fromX, float fromY, float fromZ,
    float toX, float toY, float toZ,
    float radius,
    long expiresAt
) {}
```

实现规则：

- 第一次恢复只拒绝进入失败第一路点对应的 PATH 格，或拒绝与失败线段重合的第一条边。
- 第二次在同一位置失败时，才扩展为约 `0.5～0.75m` 的一格邻域。
- Z 必须参与匹配，建议只影响 `|edgeZ - blockedZ| < 0.7m` 的同层边，不能封锁楼上/楼下。
- TTL 建议 `3～5秒`；NPC 恢复进度后立即清除。
- 这是每 NPC 的临时信息，不增加实例全局 `obstacleVersion`，避免一只怪的拥挤问题使全实例路径缓存失效。

### 8.3 A* 边过滤

复用 `PathData.EdgePassability`，但恢复期 predicate 只执行廉价坐标/格子比较：

```text
普通请求：passability = null
恢复请求：passability = edge 不属于当前 NPC 的短期失败路段
```

禁止把 `GeoService.canPassWalker` 直接作为所有 A* 扩展边的 predicate。正确流程是：

1. A* 用 PATH 拓扑和短期失败边过滤找到候选路线。
2. PATH LoS 平滑候选路线。
3. 只对最终保留的路线段做 GEO 校验。
4. 某段 GEO 不通时，把该段记录为新的失败段，最多再重算一次。

这样 GEO 调用数量与最终路点数相关，而不是与 A* 扩展边数相关。

### 8.4 恢复请求与缓存

- 带 `BlockedSegment` 的恢复请求默认绕过普通结果缓存，防止命中刚刚返回同一路线的 `500ms` 缓存。
- 恢复结果也不写入普通共享缓存，因为失败路段只对当前 NPC、当前时刻有效。
- 如果以后确实需要缓存恢复结果，缓存键必须包含失败路段签名和同层 Z，不能只使用普通起终点格。

### 8.5 节点预算与重试

- 保留 `50000` 硬上限，第一阶段不设计复杂的距离公式预算。
- 必须记录实际 `processedNodes` 分布，再决定是否增加快速预算层。
- `NODE_LIMIT`、`TIMEOUT`、`QUEUE_EXPIRED` 都属于瞬时资源失败，不应立即触发回家。
- 同一恢复事件的第二次 A* 可以使用相同上限，但必须已经改变失败路段或目标偏移；禁止完全相同请求连续重放。

## 9. 路径平滑（Line of Sight）

### 9.1 当前基础

`PathService.simplifyPath` 已从起点开始贪心尝试跨越中间点，本质上已经是 PATH Line of Sight 平滑。重构不需要另写一套 Funnel 或字符串拉直算法。

### 9.2 改进后的生成期平滑

推荐两阶段校验：

1. **PATH LoS：** 使用 `MapData.canWalkStraight` 找从当前锚点能够直达的最远 PATH 路点。
2. **最终段 GEO 校验：** 仅对平滑后保留的线段调用 `canPassWalker`。

如果某个长线段 PATH 可直达但 GEO 不通：

- 不让整条路径直接变成 `null`。
- 回退到该区间内更近的原始 PATH 路点。
- 对回退后的最终段再次校验。
- 找不到任何通过段时返回失败段信息，让恢复 A* 绕开，而不是在移动阶段反复撞击。

### 9.3 平滑限制

- 地面路线保持 PATH Z，禁止用直线插值后再以 GEO 覆盖。
- 每次只在原始 A* 路径内部跳点，不能跨到另一个 Z 层。
- 对长地面段继续保留当前约 `49m` 的分段上限，避免 GEO 或客户端移动表现跨越过长。
- 空间路径继续保留当前 `50m` 左右的直线限制、地形净空和水体边界检查。
- 平滑只在 A* worker 或路径结果处理阶段执行，不在每个移动 tick 全路径重算。

## 10. Waypoint Skip

### 10.1 作用

生成期平滑解决静态冗余，运行期 Skip 解决以下变化：

- 目标已经移动，旧路径前几个点不再必要。
- NPC 经过局部避障后，当前位置可以重新接入更远路点。
- 路点很密，当前位置已越过第一个路点但没有满足 `0.05m` 精确到达阈值。
- 小范围拥挤使 NPC 偏离原线，但后续路径仍可直达。

### 10.2 有界前视

每次最多检查后续 `3` 个路点，优先从最远候选向近处检查：

```text
候选 = min(currentIndex + 3, lastIndex)
若当前位置能直达候选：跳过中间点
否则检查更近候选
都失败：保持当前第一路点
```

性能规则：

- 正常移动最多每 `250～300ms` 检查一次。
- 刚安装新路径、刚完成局部避障或刚进入 `SUSPECTED` 时允许立即检查。
- 每轮最多 3 次廉价 PATH 段验证；只有最终准备采用的候选再做一次 GEO 校验。
- 使用障碍版本和起终点小格做 `200ms` 左右的短缓存。
- 不扫描完整路径，不为每个候选启动 A*。

### 10.3 路点到达容差

当前 `0.05m` 三维精确到达对坡地和群体避让偏严格。建议：

- 路点消费继续优先使用三维距离。
- 若 NPC 已沿路径方向越过路点，且到下一路点的线段验证通过，可直接消费当前点。
- 中间路点可使用与速度相关、上限约 `0.2～0.3m` 的容差。
- 最终攻击点和回家点保持更严格规则，避免提前完成业务状态。

## 11. 局部避障

### 11.1 复用现有管理器

继续使用 `NpcCrowdManager` 的：

- 世界/实例隔离。
- 4m 空间桶。
- 3×3×3 邻桶查找。
- 约 667ms 的速度预测。
- 先做廉价碰撞预测、再做通行检测。
- GEO 检测在同步锁外执行。

不新增新的 `LocalAvoidanceService`。

### 11.2 候选顺序

对当前期望水平向量按以下顺序尝试：

```text
直行
+15°, -15°
+30°, -30°
+45°, -45°
```

左右顺序使用 NPC `objectId` 的稳定奇偶或哈希决定，避免面对面 NPC 永远选择同一侧造成镜像死锁。不要每 tick 随机左右，否则客户端会看到方向闪烁。

只在恢复第二轮仍失败时，才考虑 `±60°`；正常局部避障不应扫描完整 360°。向后移动容易造成怪物撤退、路径抖动和封包方向反复，不作为默认候选。

### 11.3 步长

- 正常拥挤避让使用当前 tick 能移动的距离，不额外加速。
- Stuck 恢复探测目标使用 `1.0～1.5m`，但真实单 tick 位置推进仍受速度限制。
- 候选路径验证的是“短期局部目标”，不是把 NPC 立即移动 1.5m。
- 对大型碰撞体，步长可取 `max(1.0m, collision * 1.5)`，上限建议 `2m`。

### 11.4 坡地 Z 处理

这是下坡稳定性的关键规则：

- 旋转的是 XY 方向，不能把原始 `deltaZ` 乘以 `cos(angle)` 或在 180° 时翻转。
- 每个候选 XY 都调用廉价 PATH 同层投影，取得候选 `pathZ`。
- 同层判定沿用 PATH 层容差，建议优先 `<0.7m`，并限制相邻步 Z 变化符合当前路径坡度。
- 找不到同层 PATH 节点时拒绝该候选。
- GEO 只验证从当前 PATH Z 到候选 PATH Z 是否可通行。

推荐候选流程：

```text
旋转 XY
  → 投影到当前 PATH 层得到 Z
  → 邻居碰撞预测
  → PATH 短段可达
  → GEO canPassWalker
  → 选择第一个通过候选
```

### 11.5 防抖

- 选中某一侧后至少保持 `500～800ms`，除非该侧明确不可通行。
- 已取得有效进度时不要每 tick 重新选择角度。
- 局部目标变化不应每次都发送 `NPC_STARTMOVE`；沿用当前 `200ms` 追击目标广播节流。
- 只有角度变化超过小阈值或候选侧改变时才认为方向变化。

## 12. 目标点动态偏移

### 12.1 问题

大量 NPC 追同一玩家时，即使最终会按攻击距离停下，A* 的目标仍是玩家中心：

- 末段路线高度重合。
- 所有 NPC 在同一个狭窄点竞争。
- 玩家移动时，大量路径终点同时漂移并重寻。
- 下坡时多个 NPC 在同一路线上互相推挤，放大跳动和停顿。

### 12.2 稳定攻击环槽位

给每个追击 NPC 分配目标周围的稳定槽位：

```text
target center
    + 当前攻击距离内的环形半径
    + 基于 owner objectId 的稳定角度槽
```

建议第一阶段只对地面近战 NPC 启用：

- 主方向使用“从目标朝 NPC”的径向方向，避免无意义绕到目标背后。
- 在径向方向附近按稳定哈希分配 `-60°～+60°` 的槽位。
- 半径应小于实际攻击停距，并考虑双方碰撞体；最终仍由现有攻击距离判断决定是否停下。
- 槽位点必须投影到目标所在 PATH 层，并通过短段/节点有效性验证。
- 槽位无效时依次尝试相邻槽，全部失败才回退目标中心。

### 12.3 更新条件

槽位不能每 tick 随机变化。只在以下情况重算：

- 切换目标。
- 目标移动超过约 `1m`。
- 当前槽位被动态障碍阻断。
- 同一槽位持续 Stuck。
- NPC 已绕到目标另一侧，旧槽位会造成明显回头。

保留现有 `2m` 路径终点漂移阈值；只更新槽位坐标不等于立即取消仍有中间路点的旧路径。

### 12.4 远程、飞行和特殊 NPC

- 远程 NPC 的理想距离与技能选择有关，第一阶段不统一处理。
- 飞行/游泳需要三维槽位和净空校验，沿用空间路径后单独扩展。
- Boss、大型 NPC 或真端 AI 明确指定位置的 NPC 应允许关闭目标偏移。

## 13. 最近 PATH 节点与最终兜底

### 13.1 最近同层节点

新增一个有严格边界的查询：

```text
nearestPathPoint(x, y, z, maxRadius, maxVerticalDelta)
```

推荐规则：

- 按 0.5m PATH 格做螺旋或环形搜索。
- 半径依次 `0.5m、1.0m、1.5m、2.0m`。
- 最大垂直差默认 `0.7m`；第二次恢复可放宽到 `1.0m`，但不能跨层。
- 候选必须能从当前位置 GEO 直达，或至少有一个短局部候选可达。
- 找到第一个最近可达候选立即停止，不扫描大范围地图。
- 只在恢复 A* 已失败后调用，不进入正常移动热路径。

### 13.2 使用方式

1. 当前起点 `INVALID_POSITION`：先找最近同层节点，以它作为 A* 起点。
2. 当前路点附近反复 Stuck：找当前位置附近的可达节点，先短距离接入，再从该节点重算。
3. 回家路径起点无效：先接入最近节点，再向巡逻点或出生点 A*。

### 13.3 回家与传送

战斗恢复耗尽后继续使用现有真端策略：

- `pull_target`：最多现有次数，然后回家。
- `abandon_target`：清目标，停止追击。
- `return_to_sp`：清仇恨，按 PATH 返回巡逻点或出生点。

回家阶段：

- 同样使用 Stuck 检测、局部避障和失败路段 A*，但不再应用目标攻击环偏移。
- 优先返回当前巡逻点，缺失时返回出生点。
- 普通回家继续保留 `60秒` 上限；特殊 `SP` 行为保留 `30秒` 上限。
- 只有回家恢复也耗尽或超过现有超时，才使用当前位置恢复/传送完成，避免怪物永久留在战斗区域。
- 不应因为一次 `TIMEOUT`、`REJECTED` 或队列满就立即传送或回家。

## 14. 性能设计

### 14.1 热路径预算

| 动作 | 频率 | 复杂度 | 分配要求 |
|---|---:|---:|---|
| 移动插值 | 每 100ms | O(1) | 沿用现有 |
| Stuck 时间检查 | 每 100ms | O(1) | 零对象分配 |
| 进度采样 | 每 500ms | O(1) | 零对象分配 |
| 邻居查询 | 需要避障时 | 局部桶 O(k) | 复用临时列表可后置优化 |
| Waypoint Skip | 每 250～300ms，最多 3 点 | O(1) 有界 | 不复制整条路径 |
| 局部角度候选 | 仅碰撞/Stuck，最多 7 个 | O(k) 有界 | 早停 |
| A* | 仅新目标、明显漂移或恢复 | O(nodes log nodes) | worker 执行 |
| 分层 block A* | 跨至少 8 个 block | 最多 2048 个抽象 block | 邻接按需缓存 |
| 分层 portal 细化 | 仅分层命中 | 总计最多 8192 个低层节点 | 失败回退普通 A* |
| 最近节点 | 仅恢复末段 | 最多半径 2m 的有界格 | 早停 |

### 14.2 A* 线程与移动线程

- A*、路径平滑和恢复重算继续在 `PathService` worker 中执行。
- 移动线程只提交请求、收集完成结果、执行 O(1) 检测和有界局部检查。
- 禁止在 `MoveTaskManager` 的 ForkJoin worker 中同步等待 A*。
- GEO 线段检查如果可能较重，应在路径 worker 中完成；移动 tick 只做一个短局部步的 GEO 检查。
- 每只 NPC 保持一个在途请求，目标变化只在漂移阈值超过后取消。

### 14.3 缓存

保留当前：

- `2m` 起终点量化。
- `500ms` TTL。
- `1024` 最大结果。
- 障碍版本进入缓存键。

建议修正：

- 缓存键使用真正提交给 A* 的不可变坐标快照。
- 空间路径加入碰撞体/净空分桶；不同体型不能错误共享路线。
- 普通地面路线可继续共享。
- 恢复请求绕过普通缓存。
- `NO_PATH` 仍可短缓存，避免怪群对同一无路目标重复全量搜索。

### 14.4 在途请求合并

只有指标显示大量相同 key 同时排队时再实现：

```text
inFlight.computeIfAbsent(cacheKey, submit A*)
```

完成后每个调用方拿路径副本，最后一个订阅者取消时才考虑取消底层任务。实现前必须先保证 key 包含：

- 世界、实例。
- 障碍版本。
- 地面/飞行/游泳模式。
- 空间路径净空分桶。
- 实际起终点快照。

恢复请求不参与合并，因为它包含每 NPC 私有失败路段。

### 14.5 背压

继续使用当前优先级队列和 `256` 容量，不先引入复杂调度器。增加以下规则即可：

- Stuck 恢复请求与普通追击请求同为高优先级，但受每 NPC 冷却和最大尝试限制。
- 回家/位置请求继续低于追击，但至少保留当前 `1000ms` 超时。
- 队列超过 75% 时，延长普通目标漂移重寻冷却，不影响已确认 Stuck 的首次恢复。
- 队列满时保留旧路径或局部移动，不能清空路径后原地等待。
- 若后续发生恢复请求饥饿，再增加极小的全局 token budget，不先实现多级复杂公平队列。

### 14.6 网络广播

- 保留追击目的地 `200ms` 广播节流。
- 局部避障侧向保持期间不重复发送 `NPC_STARTMOVE`。
- Waypoint Skip 只在实际目标路点改变且超过方向阈值时广播。
- 验收时比较 `SM_MOVE` 每 NPC 每秒数量，重构后不应因恢复逻辑显著增加。

## 17. 正确性不变量

任何实现都必须保持：

1. PATH 路点 Z 不能被 GEO Z 覆盖。
2. 平滑、Skip 和局部避障不能跨 PATH 层。
3. 目标小幅移动时保留仍有中间点的路径。
4. 队列满、超时或取消不能直接等价为“无路”。
5. 一只 NPC 的临时失败路段不能污染整个实例的障碍版本。
6. 动态门、盾或实例障碍变化仍通过 `obstacleVersion` 使旧缓存失效。
7. 正常 A* 不对每个扩展边执行 GEO 射线。
8. 同一 NPC 同时最多一个 A* 请求。
9. 回家失败策略不能无限重试，也不能第一次失败就传送。
10. 局部避障候选必须受速度预算限制，不能发生真实位置跳跃。
11. 目标偏移必须稳定，不能每 tick 随机更换。
12. 旧异步结果不能覆盖新目标或新障碍版本的路径。

### P0-C：失败路段 A* 恢复

当前实现（2026-07-17）：

- `BlockedSegment` 只过滤当前 NPC、当前同层的失败第一边，TTL 为 5 秒。

- `//geo path` 已输出恢复提交、成功、失败及控制器重算指标。

### P1-A：Waypoint Skip 与平滑硬化

涉及：

- `PathService`
- `NpcMoveController`
- `PathServiceCompressionTest`
- `NpcMoveControllerPathTest`

内容：

- 生成期 PATH LoS + 最终段 GEO 校验。
- GEO 长段失败时回退较近原始路点。
- 运行期最多 3 点前视。
- 越过路点判定。

验收：路径点减少、墙体不穿透、坡地 Z 保持，移动目标不会频繁回到旧的第一路点。

当前实现（2026-07-17）：

- 生成期先用 PATH LoS 选择最远候选，再用 GEO 校验最终保留线段；GEO 拒绝长段时逐步回退到较近原始 PATH 路点。
- 地面平滑段最长保持约 `49m`，单个锚点最多检查 128 个原始半米格点，避免超长路径无界扫描。
- 运行期每 `250ms` 最多前视 3 个路点；只对 PATH 可直达的候选执行 GEO，成功后才裁掉前置路点。
- 路点切换、安装新路径和进入 Stuck `SUSPECTED` 时会尽快重新检查；PATH Z 始终保留。
- `//geo path` 已输出平滑前后点数、GEO 线段检查/拒绝及 Waypoint Skip 尝试/成功数。

### P1-B：局部避障升级

涉及：

- `NpcCrowdManager`
- `NpcMoveController`
- `PathService` 的同层短步投影接口
- `NpcCrowdManagerTest`

内容：

- 候选顺序改为稳定左右的 `15/30/45°`。
- 候选 Z 来自 PATH 同层投影。
- 侧向选择保持 500～800ms。
- Stuck 局部恢复和普通拥挤共享同一候选器。

验收：下坡群怪不因侧向候选出现 Z 跳变；面对面和同向拥挤能够分流。

当前实现（2026-07-17）：

- 普通候选固定为直行、稳定左右顺序的 `±15°/±30°/±45°`，不再扫描 360°，也不默认后退。
- 侧向旋转只修改 XY；候选 Z 不再乘 `cos(angle)`，不会在坡地被压低或翻转。
- 碰撞预测通过后，候选 XY 才投影到当前同层 PATH Z，再执行 PATH 短段与 GEO 检查。
- 选中的左右侧保持 `667ms`；稳定奇偶顺序作为无历史选择时的默认侧。
- 普通拥挤与连续失败后的 `1.5m` 局部恢复共用同一候选器；无安全前向候选时停止本帧，不强行穿过其他 NPC。

### P1-C：稳定目标槽位与最近节点

涉及：

- `NpcMoveController`
- `PathService`
- `PathData`

内容：

- 地面近战目标环槽位。
- 目标切换/移动/槽位阻塞时更新。
- 半径 2m 内最近同层 PATH 节点。
- 恢复耗尽后接入既有 AI 失败策略。

验收：20～50 只 NPC 追同一移动玩家时，终点和末段方向分散，A* 请求率和原地拥挤下降。

当前实现（2026-07-17）：

- 仅地面且攻击距离 `0.75～4m` 的近战 NPC 使用目标环槽位，槽位半径小于实际攻击距离。
- 槽位由 NPC/目标 objectId 与目标朝 NPC 的径向共同决定，分布在 `-60°～+60°`，目标移动满 `1m` 才重新投影。
- 槽位投影到目标所在 PATH 层；Stuck 恢复时按稳定相邻槽切换，不随机抖动。
- A* 起点无效时先尝试接入半径 `2m`、垂直差 `<0.7m` 的最近可达同层节点；两次失败路段 A* 都失败后也仅执行一次同样的接入。
- 最近节点接入仍受 GEO 短段验证和单帧速度限制；失败后继续进入既有 `pull_target`、`abandon_target`、`return_to_sp` 与回家超时策略。

### P2-A：长距离 block/portal 分层寻路

当前实现（2026-07-17）：

- 参考 `hugoscurti/hierarchical-pathfinding` 的 Cluster、`INTER/INTRA` 和逐层细化模型。
- 直接使用官方 16m PATH block 和跨块 portal，不重新切格，不复制第二份低层节点图。
- 仅跨至少 8 个 block 的地面长路径启用；短追击、Waypoint、飞行和游泳保持旧路径。
- block A* 最多展开 2048 个抽象节点；随后逐 block 搜索可达 portal，所有细化共享 8192 个低层节点预算。
- portal 细化继续使用真实 PATH Z、同层连接和 `BlockedSegment`；任一段失败后从原起终点执行普通 A*。
- block 抽象 A* 无通道或达到抽象节点上限时同样计入分层回退，并保留实际 `abstractNodes`；线程中断只计尝试，不误计为分层成功。
- `gameserver.geo.path.hierarchical.enable` 可独立关闭；仓库运行配置默认启用，Java 配置缺省值保持关闭。
- `//geo path` 输出 `hierarchical=尝试/成功/回退` 与 `abstractNodes`。

验收：合成跨 block 障碍地图中，分层搜索低层展开量小于普通 A* 的一半；运行时障碍迫使路线离开抽象通道时，自动回退后仍找到路线；抽象图无通道时也会保留分层尝试、回退和抽象节点指标。真实资源复核为 `scanned=185 / loaded=185`。

### P2-B：其余仅按指标实施的性能增强

候选项：

- 同键在途请求合并。
- 队列高水位时延长普通重寻冷却。
- 按实际 `processedNodes` 分布设计两级预算。
- 局部候选数组/列表复用，减少分配。
- 更细的实例级恢复 token budget。

没有指标证明瓶颈前不实施 P2-B。

## 19. 测试方案

### 19.1 单元测试

#### Stuck 检测

- 直线正常移动持续产生有效进度。
- Z 下降但 XY 正常前进不判 Stuck。
- 横向绕行且到路点距离下降不判 Stuck。
- 位置有抖动但没有路线进度时最终判 Stuck。
- Root、Stun、CAST、等待路径、进入攻击距离时暂停。
- 路点切换和目标切换重置采样。
- 长 tick/服务器暂停不误判。

#### 恢复状态机

- 确认 Stuck 后按 Skip → Local → Replan → Nearest → Exhausted 顺序。
- 每阶段成功立即回 NORMAL。
- A* 冷却和最大次数生效。
- 目标移动或障碍版本变化允许新的恢复周期。
- 瞬时队列失败不进入最终回家。

#### A* 失败路段

- 普通 A* 选择最短边。
- 过滤失败第一边后选择替代路线。
- 过滤只影响同一 Z 层。
- TTL/恢复完成后过滤消失。
- 恢复请求不命中普通缓存。
- 无替代路线返回明确 `NO_PATH`。

#### 平滑与 Skip

- 能直达更远点时删除中间点。
- GEO 阻挡长段时回退较近点，不返回整条空路径。
- 最多检查 3 个点。
- 不跨层、不改变最终 PATH Z。
- 旧路径快照不能消费新路径。

#### 局部避障

- 候选顺序为稳定的 `±15/±30/±45°`。
- 两只面对面 NPC 选择不同侧。
- 坡地候选 Z 来自 PATH 投影，不随角度反转。
- 候选长度不超过移动预算。
- 碰撞预测失败的候选不调用 GEO。
- 第一个有效候选后立即停止。

#### 目标偏移

- 同一 NPC/目标组合槽位稳定。
- 多个 objectId 分散到不同槽位。
- 目标小幅移动不切换槽位。
- 无效槽位回退相邻槽或中心。
- Boss/特殊类型禁用时保持旧行为。

#### 分层寻路

- 少于 8 个 block 的路径保持 `DIRECT/LOW_LEVEL`。
- 长路径能通过 block A* 和真实 portal 逐段细化。
- 分层细化的低层展开量显著低于同图普通 A*。
- 动态障碍使抽象路线失效时回退普通 A*。
- 抽象图无通道或达到节点上限时仍计入回退，线程中断不计为成功。
- 多层、单向或不可达 portal 不会生成错误路径。
- 线程中断和节点预算在抽象层与细化层都能终止。

## 20. 性能验收目标

先采集旧版本基线，再比较新版本。以下为建议目标，不作为未测量前的硬承诺：

- Stuck 检测自身不增加 GEO 或 A* 调用。
- 确认 Stuck 后 P95 在 `5秒` 内恢复前进或进入明确失败策略。
- 单只持续追击 NPC 正常情况下 A* 提交率不超过约 `2次/秒`。
- 正常负载路径队列 P95 低于容量的 25%，不出现拒绝。
- A* P99 仍应低于当前 `250ms` 追击超时，超时率和拒绝率不高于旧版本。
- 50 只怪下坡场景中，`SM_MOVE` 每秒总量增长不超过旧版本约 10%。
- 路径平滑后的平均点数不高于旧版本，同时 GEO 最终段检查数与保留点数同量级。
- `MoveTaskManager` 周期不能因 Stuck 检测出现可观察的长尾增长。
- 恢复 A* 占总 A* 请求的比例应保持低位；若长期高于 10%，优先修路径/局部移动原因，而不是继续提高 worker。
- 分层 `hierarchicalFallbacks / hierarchicalAttempts` 若长期高于 30%，应先关闭开关并检查 block 抽象粒度或 portal 细化，不提高节点预算掩盖。

## 21. 风险与防护

| 风险 | 表现 | 防护 |
|---|---|---|
| Stuck 误报 | 正常转弯或施法触发恢复 | 500ms 采样、3 窗口确认、暂停条件、Shadow 模式 |
| A* 风暴 | 怪群同时重算 | 每 NPC 单请求、750ms 冷却、最大次数、队列背压 |
| 相同路线循环 | 重算后继续撞同一点 | 失败路段进入恢复请求，绕过普通缓存 |
| GEO CPU 暴涨 | A* 每边调用射线 | 正常 A* 只走 PATH；只校验最终少量线段 |
| 坡地 Z 跳动 | 侧向避障改变 Z | 候选 XY 投影回同一 PATH 层，禁止旋转 deltaZ |
| 跨楼层 | Skip/候选找到另一层 | Z 参与同层匹配，保持 `<0.7m` 层容差 |
| 方向闪烁 | 每 tick 左右随机 | 稳定哈希侧、500～800ms 保持、广播节流 |
| 旧结果覆盖新目标 | 异步结果晚到 | requestId + obstacleVersion 校验 |
| 回家过早 | 队列瞬时失败被当无路 | 明确状态分类，瞬时失败只退避 |
| 大型 NPC 复用小型路线 | 空间路径净空不同 | 缓存键加入移动模式和 clearance 分桶 |
| 分层抽象路线不真实 | block 有 portal 但当前层内部不连通 | 每个 `INTRA/INTER` 段用低层 PATH 验证，失败回退普通 A* |
| 分层首次查询变慢 | portal 细化失败后又跑普通 A* | 8192 细化预算、至少 8 block 门槛、独立开关与回退率指标 |

## 22. 回滚策略

- 总开关 `gameserver.geo.path.recovery.enable` 可关闭新恢复状态机，回到当前路径行为。
- `gameserver.geo.path.hierarchical.enable` 可只关闭分层寻路，普通 A*、Stuck 恢复和 PATH 文件格式不变。
- Shadow 检测、Waypoint Skip、目标偏移应有独立内部 feature flag，开发阶段逐项启用；稳定后只保留必要的线上总开关。
- 不改变 PATH 文件格式，不需要回滚地图资源。
- `PathData.searchAStar` 的普通调用保持原语义；恢复边过滤是可选参数。
- 每个阶段形成独立小提交，出现回归时可单独回退，不把 Stuck、目标偏移和性能合并成一次大提交。

## 23. 明确不做

- 不替换 A* 为 Dijkstra、D*、JPS、Recast/Detour 或客户端寻路。
- 不重新生成 PATH 数据来解决尚未证明的数据问题。
- 不把 GEO 当成 PATH 的高度来源。
- 不在每个移动 tick 执行完整 A*。
- 不在每个 tick 对整条路径做 LoS 扫描。
- 不在正常 A* 的每个扩展边执行 GEO 射线。
- 不引入第三方 RVO/ORCA 依赖。
- 不用随机方向、随机目标点掩盖确定性错误。
- 不把瞬移回家当作首选恢复。
- 不先增加 worker、队列或节点上限来掩盖重复重寻。

## 24. 最终推荐默认行为

```text
正常追击：
  使用不可变起终点快照提交 A*
  保留现有 2m 目标漂移迟滞
  跨至少 8 个 PATH block 时先做 block/portal 分层寻路，失败回退普通 A*
  PATH LoS 平滑并校验最终段
  每 500ms 采样进度
  每 250～300ms 最多前视 3 个路点

确认 Stuck（约 1.5s 无有效进度）：
  先跳更远路点
  再尝试稳定侧的 ±15/±30/±45°
  失败后记录同层失败路段
  750ms 冷却下最多重算 2 次 A*
  恢复请求绕过普通缓存
  仍失败则寻找 2m 内最近同层 PATH 节点
  5s 后执行真端 pathfind fail reaction

怪群追击：
  保留现有空间桶和速度预测
  地面近战使用稳定攻击环槽位
  候选 Z 始终投影到 PATH 同层
  不随机换边，不扩大网络广播频率

回家：
  继续使用 PATH、Stuck 恢复和最近节点
  返回巡逻点优先，否则出生点
  仅在现有 30/60s 超时后做最终位置恢复
```
