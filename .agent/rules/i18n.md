# Internationalization, Comments, and Terminology Rules

## Bilingual Comments

1. Every new or modified code comment must contain both Chinese and English in the same comment block and convey the same meaning in both languages. Do not merely translate identifiers or add comments without useful design information.
2. Every new or modified class, interface, enum, and record must have bilingual class-level Javadoc that explains its responsibility, boundaries, and any relevant lifecycle or thread-safety constraints.
3. Important methods must have bilingual method-level Javadoc. Important methods include public APIs, core business flows, state transitions, protocol handling, transaction or concurrency boundaries, lifecycle entry points, and methods with non-obvious side effects or failure semantics. Document parameters, return values, side effects, exceptions, and critical preconditions as applicable.
4. Simple getters and setters, obvious delegations, and short overrides that add no contract do not require method comments. Any comment that is added or modified must still be bilingual.

## Localized Logging

1. Every new or modified logging call must resolve its text through `I18n.get(...)`. Do not place raw strings directly in logging calls or use `String.format(...)` to assemble operator-visible log messages.
2. Every message key must be added to both `src/main/resources/messages.properties` and `src/main/resources/messages_zh_CN.properties`, with matching placeholders and semantics.
3. Changes to logging require `LocalizedLogCallsTest` and message-key parity across both bundles as acceptance criteria.

## Terminology

1. Use `docs/aion-game-terms-en-zh.md` as the authority for Chinese and English terms in player-visible text, comments, and logs.
2. When the glossary already defines a term, use its canonical translation instead of inventing a synonym.
