# 国际化、注释与术语规范 (Internationalization, Comments, and Terminology Rules)

## 中英双语注释 (Bilingual Comments)

1. 所有新增或修改的代码注释，必须在同一个注释块中同时包含中文和英文，且两种语言表达相同的含义。切勿仅机械翻译标识符名称，或添加缺乏有效设计信息的空洞注释。
2. 所有新增或修改的类（class）、接口（interface）、枚举（enum）和 record，必须包含双语的类级别 Javadoc，说明其核心职责、边界以及相关的生命周期或线程安全约束。
3. 重要方法必须包含双语的方法级别 Javadoc。重要方法包括：公共 API、核心业务流程、状态流转、协议处理、事务或并发边界、生命周期入口点，以及具有非显式副作用或失败语义的方法。视情况明确记录参数、返回值、副作用、异常以及关键前置条件。
4. 简单的 getter 和 setter、显而易见的委托调用（delegations）以及未增加额外契约的简短重写方法无需添加方法注释。但凡添加或修改的任何注释，均必须保持中英双语。

## 本地化日志 (Localized Logging)

1. 所有新增或修改的日志调用，其文本内容必须通过 `I18n.get(...)` 获取。切勿在日志调用中直接编写原生字符串，亦不可使用 `String.format(...)` 拼装面向运维人员的日志消息。
2. 每个日志消息 key 必须同时添加到 `../../src/main/resources/messages.properties` 和 `../../src/main/resources/messages_zh_CN.properties` 中，且占位符数量与语义必须完全一致。
3. 修改日志后，必须以通过 `LocalizedLogCallsTest` 以及两个资源包（bundle）之间的消息 key 对齐作为验收标准。

## 术语规范 (Terminology)

1. 涉及面向玩家的文本、注释及日志中的中英文术语时，以 `../../docs/aion-game-terms-en-zh.md` 作为权威参考依据。
2. 当术语表中已有统一定义时，必须使用其规范译名，严禁自行创造同义词。
