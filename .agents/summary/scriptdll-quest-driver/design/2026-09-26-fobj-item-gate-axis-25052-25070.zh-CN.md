## 2. 结论：两行分属两个既有通道，不能同批

### 2.1 25070 ⇒ SimpleTalk 的 **P0c-10o 工作物品门**通道（可行，最快）

- 判据：`item_check=1 且无 collect_item` 时校验目标 = 接取发放的工作物——`RetailSimpleTalkDefinitionCompiler`
  （约 226/360/1079/1134 行）已实现该报告流与门；25070 的 `check_item1_1 = quest_25070a 1` 正是此形。
- 额外只差**步词汇**：单步 TalkFOBJ 的推进边（`TalkToNpc(fobjNpc, USE_OBJECT)` + `SetVariable(var0,lastRow)`）——
  混合链合成器的 talkfobj 分支已有同形发射（15601/18931），可抽公共件或在 SimpleTalk 侧补一条 FOBJ 步。
- 遗留对照：真端「工作物接取即发 + 交互推进 + planner 回收」与遗留「交互 give-item + 推进」在 25070 上**等价**
  （遗留无 HasItem 门、无 drop ⇒ 无合同损失）。
- 待核：`can-act(731552, ACTION_ITEM_USE)` 自环是否必需——遗留有、真端无 drop ⇒ 按 10011/1141 判例无需
  （`QuestInteractionObjectValidator` 只对**有 drop** 的 quest_use_item 源要求门）。

### 2.2 25052 ⇒ 采集族 + **FOBJ 掉落源**通道（较慢，须新词汇）

- 判据：零售 `collect_item1 = quest_25052a 5` 是**规范要求**（客户端显示 0/5），而混合链的 talkfobj 分支
  **不带物品门** ⇒ 若直接放行会静默丢掉「交 5 件」合同（假采纳）。
- 需要的词汇：
  1. 路由谓词：单步 talkfobj **且** `metadata.inventoryItems()` 非空 → 采集族（`collect_item*` 经
     `RetailQuestMetadataCompiler` 落 `inventoryItems`，可作机器判据）；
  2. 掉落源 = FOBJ 模板：`drop_monster_1` 解析到交互物（`ai=quest_use_item`）⇒ 采集族必须为该源发
     START 态 `CanAct(npc, ACTION_ITEM_USE)`（`RetailSimpleCollectItemDefinitionCompiler:323` 已有同形发射 +
     `RetailHandinDialogFlowCompiler:155` 的掉落箱路由可复用）；
  3. 交付/失败/完成路由与 `select_none_1` 阶梯（4770 页族）按客户端登记补齐——**当前登记表无行，须先补证据**。
- 判据：接取=交付 NPC 不同（Redelf→Soglo），交付边带 `has-item 5`；完成边按 4 个 selectable 分支展开。
