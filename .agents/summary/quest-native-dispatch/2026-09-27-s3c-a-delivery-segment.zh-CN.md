## 1. 交付段独立接管谓词（本片的核心）

```
canonicalDelivery = ( 块路径： (canonicalAccept ∨ systemGrant) ∧ 有 NPC_REPORT 块 )
                  ∨ ( A 形： ∃ 翻面记录 ∧ ¬∃ 竞争翻面 )
```

| 形 | 判据（全部派生，无硬编码行号） | 判例 |
|---|---|---|
| 块路径（接取已接管） | `canonicalAccept ∧ 有报告块`（S2 原谓词，逐字不变） | S2 203 行 / 2611 |
| 块路径（系统发放） | `systemGrant ∧ 有报告块`——系统发放**无接取段可接管**，交付段独立成片。实测报告块行 205 行中无 `NPC_START` 块的仅 2611 与 35017 ⇒ 新增面恰 1 行 | 35017 |
| A 形翻面 | 源节点**投影 START** ∧ 目标 `reward` ∧ 交付 NPC ∈ **交付作用域** ∧ 动作 ∈ `SELECT_QUEST_REWARD`/`SET_SUCCEED`/`SETPRO1..3` ∧ **无竞争翻面** | 26 行（+24202/80752/80320） |

**交付作用域** = 真端 `reward_npc_name` 解析集，**空集时回落客户端交付 NPC 登记**
（`quest_client_reward_npcs.tsv`，与单步路径同源）：判例 35024/35025/35026（`LF4_GuardianOfDivine` 在
npc 注册表里不存在）与 45024/45025/45026（`DF4_GuardianOfTower`）——两变体（799800/799801、
799842/799843）各得一条边；判例 80752（`event_warewolf` → 833584，成员关系而非单元素集）。

**竞争翻面** = 指向 `reward`、源同样投影 START、却落在**交付作用域之外**的翻面记录 = D 类中间人
premature 形（判例 4209/21033/21455/30711/30761），按 (iii) 裁定留 W2——谓词与验证同源，边界可机检。

## 2. 三处前置（prep §1）的实装形态

1. **G-4「被承担」分支（条件侧）**：退场的阶段门（`VAR_IS`/`VAR_AT_LEAST`）除"被规范边源节点投影蕴含"
   外，新增**被规范交付边 conditions 逐字承接**通道（`carriedDeliveryGates`，token 逐字相等才放行）。
   判例 35010/35018/35024/35025/35026/45024/45010… 的投影 `var0=-`（锚定不蕴含）⇒ 走承接通道。
2. **`retiredChainGate` 读 `I` 记录 + 接管行不展开展开旧检查对**：`I` 记录（`item_check` 的 39/20002 对的
   真端来源）与退场 `R` 记录**同轴**收集进门；`canonicalDelivery` 的行**跳过** `itemReportGate` 展开
   （否则规范边与旧检查对**双份**）。判例 24202：唯一门源即 I 记录（`182215465:1`，与 quest.xml
   `collect_item1=quest_24202b 1` 同物），不读则有两条 fail-open（无物可交付 / 扣物静默消失）。
3. **交付谓词解耦 + 系统发放块路径**：见 §1。

**动作侧同轴（G-1 同源）**：`SET_VAR:var0=k` 等阶段写由规范交付边的 **actions** 逐字承接
（`carriedDeliveryActions`，判例 28809/35011/35026/80752）——只收条件侧会让 packed 投影与真端写入
分家（任务书行号漂移）。**载荷既不丢门、也不丢物、也不丢阶段写**。

**层 A 交付对偶**：规范交付边占据 `(源节点, 交付 NPC, 31)` 键；同键登记记录**必须随交付段退场**——
否则 `explicitRoutes` 覆盖会把刚合成的边**反向删除**（判例 80752 的 `QUEST_SELECT s0→s0` 只推 SELECT2
页、两臂词表都不命中 ⇒ 形状静默回退旧形而指纹零漂移）。实装 `deliveryKeys` + `canonicalKeyRoute`。

**单一真源**：A 形边由 `RetailSimpleCollectItemDefinitionCompiler.canonicalDelivery(...)` 合成（与采集族、
S2 块路径同一处形状定义），过场按 S1 判据重挂（`attachMovieToRoute`，match==1 fail-closed）。

## 5. 开发期修正留痕（诚实记录）

1. **谓词先窄后宽三次**：`resolvedRewardNpcs.size()==1` → 成员关系（判例 35024 家族）→ 客户端回落
   （判例 45024 真端名在注册表不存在）；每次都由**冻结跑**的拒绝/零漂移证据驱动，不靠猜。
2. **一次 stale 读数假象**：`/tmp/*.tsv` 是冻结模式**断言 problems 为空后**才写；中途两次编译失败让
   文件停留旧值，我据此误判"8 行零漂移"。教训：**冻结产物必须核对 mtime/文件是否被本次运行重写**，
   否则会把"没跑成"读成"没变化"（此坑与 QE-084 的"裸 surefire 验旧字节码"同族）。
3. **层 A 在交付侧同样成立**（80752）——S3b 只在接取侧登记了这条判据，本片补上交付对偶。
4. **`systemGrant` 块路径放行的面**先按数据实测（报告块行 205 行 − 有 START 块者 = 2611/35017），
   再写谓词 ⇒ 新增面恰 1 行、切片边界不变。
