# Q19048、Q23704、Q23708、Q29048 取证记录

- Pattern：四个任务与 Q13704/Q13708 逐项同构，都是同一 NPC 的任务物品报告页前置，而非多 NPC handoff。
- 当前 IR：`started + use-item -> reward` 直接显示 page `5`；`reward + owner + USE_OBJECT/1009` 合并成同一条 page `5` route，因此 `SELECT5(2375)` 不可达。
- Aion 5.8 客户端：`quest_q19048.html`、`quest_q23704.html`、`quest_q23708.html`、`quest_q29048.html` 都包含 `SELECT5(2375)`，其可见报告按钮均为 `1009`。
- 旧 handler：`_19048Andreas_Teachings`、`_23704Loud_Noises`、`_23708Sound_The_Alarm`、`_29048SeriphimTeachings` 都以 `USE_OBJECT -> 2375`、`1009 -> removeQuestItem -> sendQuestEndDialog` 实现该阶段；物品使用后只把任务更新为 `REWARD`。
- 修复合同：每个任务独立保留其状态、物品、奖励和 NPC ID；只拆分 `USE_OBJECT -> SELECT5` 与 `1009 -> remove-item -> page 5`，并从原生奖励完成 route 移除重复扣物。
- 自动发现的奖励一致性缺陷：旧 `quest_data.xml` 的 Q19048/Q29048 都声明 `EXP 37405 + ITEM 188508000 x1`，并由旧 handler 的 `sendQuestEndDialog` 统一结算。Q19048 的 typed metadata 已有该物品但完成 route 漏发，补充同一 `grant-reward`；Q29048 的完成 route 已发该物品但 metadata 漏项，补充 metadata。两处都由回归同时锁定 metadata 与 transaction actions。
